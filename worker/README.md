# عامل توليد الجلسة — دليل التثبيت على الـVPS

هذا العامل هو منفّذ طابور التوليد: يلتقط طلبات التوليد من جدول `generation_jobs` (يجهّزها Vercel كاملة)، ينفّذها عبر **جلسة اشتراك كلود** بأمر `claude -p` (لا API ولا مفاتيح أنثروبيك)، ويكتب النتيجة ليعرضها المتصفح.

## المتطلبات على الخادم

1. **Node.js 24 LTS** (الحد الأدنى 23.6 — العامل يعتمد تجريد الأنواع الأصلي).
2. **Claude Code مسجَّل الدخول باشتراكك**:
   ```bash
   npm install -g @anthropic-ai/claude-code
   claude login
   ```
   بعد الدخول جرّب `claude -p "قل مرحباً" --model claude-fable-5` للتأكد أن الجلسة تعمل.
3. git لاستنساخ المستودع.

## خطوات التثبيت (مرة واحدة)

```bash
# ١) الاستنساخ والتبعيات
sudo mkdir -p /opt/mind && sudo chown "$USER" /opt/mind   # أو أي مسار تفضّله (وعدّله في وحدة systemd)
git clone <رابط المستودع> /opt/mind
cd /opt/mind
npm ci

# ٢) بيئة العامل
cp worker/.env.worker.example worker/.env.worker
nano worker/.env.worker   # املأ SUPABASE_URL وSUPABASE_SERVICE_ROLE_KEY وOWNER_NAME (+ تيليجرام إن أردت الإشعارات)

# ٣) اختبار مباشر: يعالج طلباً واحداً (أو يطبع «لا طلبات») ثم يخرج
npm run worker:once
```

للاختبار الكامل: افتح مختبر المحتوى في المتصفح، ولّد بمحرّك «عبر الجلسة»، ثم شغّل `npm run worker:once` وراقب المسودة تظهر في الواجهة.

> إن كان إصدار Node أقدم من 23.6 ولا يمكنك ترقيته: `npx tsx worker/generation-worker.mts --once` يعمل على أي إصدار حديث (يُنزّل tsx عند الطلب).

## التشغيل الدائم (systemd)

```bash
sudo cp worker/mind-worker.service /etc/systemd/system/mind-worker.service
sudo nano /etc/systemd/system/mind-worker.service   # عدّل User وWorkingDirectory لمسارك (القالب يفترض مستخدماً اسمه mind والمسار /opt/mind)
sudo systemctl daemon-reload
sudo systemctl enable --now mind-worker

# المراقبة
systemctl status mind-worker
journalctl -u mind-worker -f
```

عند تحديث الكود: `cd /opt/mind && git pull && npm ci && sudo systemctl restart mind-worker`.

## كيف يتصرف العامل (مضبوط في الكود، قابل للتهيئة عبر env)

- **الطابور**: أقدم طلب `queued` أولاً، بقفل تفاؤلي (شرط id + status يمنع أي سباق).
- **حد استخدام الاشتراك**: لا يُفشل الطلب — يعيده للطابور ويُرجئ العمل ~٢٠ دقيقة، ولا يحتسبه محاولة.
- **الفشل العابر** (شبكة/ناتج مكسور): إعادة حتى ٣ محاولات ثم `failed` برسالة عربية تظهر في الواجهة.
- **رفض المحرّك** (فكرة غير صالحة للنشر): نهائي فوراً برسالة الرفض واقتراحه — لا إعادة.
- **القفل البائت**: طلب «يعمل» لأكثر من ٣٠ دقيقة (عامل مات أثناءه) يُسترد تلقائياً.
- **حلقة النقد**: تتراجع بلطف — فشلها يُبقي المسودة الأولى (نفس تدرّج مسار API).
- **الإيقاف**: `systemctl stop` أثناء تنفيذ طلبٍ يتركه «يعمل» — يسترده فحص القفل البائت عند عودة العامل.

## استكشاف الأخطاء

| العرض | السبب الأرجح | العلاج |
|-------|--------------|--------|
| «أمر claude غير موجود في PATH» | CLI غير مثبت أو systemd لا يرى PATH | ثبّت CLI؛ الوحدة تستخدم `bash -lc` أصلاً — تأكد أن claude يعمل من صدفة الدخول لنفس المستخدم |
| فشل فوري بـ«أعادت الجلسة خطأً» | انتهاء جلسة الدخول | `claude login` مجدداً من نفس المستخدم |
| الطلبات تبقى «في الطابور» بلا حراك | العامل متوقف | `systemctl status mind-worker` ثم السجلات |
| «بلغت الجلسة حدّ الاستخدام» يتكرر طويلاً | نافذة حصة الاشتراك ممتلئة | انتظار — العامل يعاود وحده؛ أو ولّد بالمحرّك «المباشر» من الواجهة مؤقتاً |
