# تشخيص عطل إنتاج (debug-prod)

## المبادئ الحاكمة (تعلّمناها بثمن)

1. **رسالة المتصفح لا تحمل السبب.** الإنتاج يحذف رسائل الأخطاء المرميّة من إجراءات الخادم ويعرض نصاً إنجليزياً عاماً — الحقيقة في سجلات runtime حصراً. الواجهات التي تتبع نمط «الأخطاء قيم لا استثناءات» تعرض السبب العربي الدقيق؛ فإن رأيت الرسالة الإنجليزية العامة فمصدرها مسار لم يُحوَّل بعد لنمط الإرجاع كقيمة، وهذا بذاته دليل تشخيصي.
2. **رسالة واحدة ≠ سبب واحد.** في حادثة سابقة حملت رسالةُ خطأ واحدة أربعة أسباب جذرية متتالية (مصفوفة ملفوفة ← رصيد ← اقتباس غير مهرَّب ← مهلة). لا تعلن الحل النهائي من أول توقيع — أصلح، انشر، ثم راقب هل تغيّر التوقيع.
3. **الرصد قبل العلاج.** إن لم تكشف السجلات السبب الخام، فالخطوة الأولى الصحيحة إضافة `console.error` موسوم للسبب الحقيقي (نمط `[analyze]`) ونشره ثم طلب إعادة المحاولة — هذا ما كشف سابقاً عطلاً خفياً عمره شهر.

## ١. التجهيز

- حدّد المشروع: المعرّفات (projectId وteamId) في `.vercel/project.json` المحلي (غير مرفوع إلى git؛ يُنشأ بـ`vercel link`). لا تكتبها في ملفات المستودع.
- أدوات القراءة: Vercel MCP (`get_runtime_errors`, `get_runtime_logs`, `get_deployment`, `list_deployments`) أو CLI (`vercel logs`, `vercel inspect`). قراءة السجلات آمنة دائماً ولا تحتاج استئذاناً.

## ٢. ترتيب القراءة (لا تعكسه)

1. **الأخطاء المجمّعة أولاً** (`get_runtime_errors` بنافذة ساعتين أو حول وقت الشكوى) — مجمّع وسريع: العناقيد، العدّ، `first/last seen`، وآخر نشر ظهر فيه كل خطأ.
2. **قارن الأزمنة والنشر:** حقل النشر الذي ظهر فيه الخطأ مقابل النشر الحيّ الحالي. **فخّ الخطأ البائت:** خطأ آخر ظهوره على نشر قديم قد يكون أُصلح أصلاً — لا تطارده.
3. **السجلات الخام** بنافذة ضيقة (±٣ دقائق حول الحدث) وبمستويات `error` و`warning` و`info` — الـ`info` ضروري: أسطر `[claude] cache_read=... out=...` و`[analyze] ...` التشخيصية تعيش فيه، وهي التي تكشف ماذا كان يجري لحظة الموت (مثال حاسم: سطر `[claude]` يسبق مباشرة `Task timed out` = النداء قُتل وهو حيّ يبثّ).
4. اربط التوقيع بجدول التواقيع أدناه. توقيع غير معروف؟ اقرأ الكود في المسار الذي يظهر في الـstack قبل أي فرضية.

## ٣. جدول التواقيع المعروفة

| التوقيع في السجل | السبب | الإجراء |
|---|---|---|
| `Vercel Runtime Timeout Error: Task timed out after 300 seconds` (504) | نداء xhigh طويل تجاوز سقف Hobby الصلب | قرار يخص صاحب النشر (توليد عبر العامل / تخفيف / ترقية) — أبلغ ولا تعالج من طرفك؛ ولا ترفع `maxDuration` فوق ٣٠٠ (يُفشل النشر كلياً) |
| `تعذّر تحليل الفكرة للنشر` | فشل مرحلة التحليل (Gemini) — ابحث عن سطر `[analyze]` المرافق للسبب الخام | حسب السبب الخام: JSON مكسور → تأكد من `responseJsonSchema`؛ مصفوفة ملفوفة → فكّ التغليف قائم في `lib/content/analyze.ts` |
| 400 `credit balance is too low` | نفاد رصيد أنثروبيك | ليس عطلاً برمجياً — أبلغ صاحب المفتاح ليشحن الرصيد، وتحقق بعده |
| `بلغ المخرج حدّ الطول الأقصى` | `stop_reason=max_tokens` — التفكير التكيّفي التهم السقف (تفاوت ٧٪→١٠٠٪ مقيس) | ارفع `maxTokens` للنداء المعني ثم `/smoke-ai` بتشغيلين |
| `رفض النموذج معالجة هذا الطلب` | `stop_reason=refusal` | افحص المدخل المرسل — غالباً محتوى المستخدم لا الكود |
| `فشل تفكيك JSON: Expected ...` | مخرج نموذج غير مقيّد بمخطط | قيّده: `responseJsonSchema` لـGemini أو `schema` لكلود |
| ما بعد الدخول: لا بيانات أو كل شيء محجوب | UID المستخدم غير مسجَّل في `app_owner` (RLS تحجب غير المالك) | سجّله (`docs/SETUP.md` الخطوة ٤) |
| البوت لا يردّ | الـwebhook غير مسجَّل أو السرّ/معرّف المحادثة غير مطابق | افحص `getWebhookInfo` وأعد `scripts/register-telegram-webhook.mjs` |
| الكرون يعيد 401 | `CRON_SECRET` غير مضبوط في Vercel أو لم يُعَد النشر بعده | اضبطه وأعد النشر |
| `Extension context invalidated` في كونسول المتصفح | ضجيج إضافات المتصفح عند المستخدم | تجاهله تماماً — ليس من التطبيق |
| نشر `state: ERROR` مع `invalid_max_duration` | `maxDuration` > سقف الخطة | أعده ≤ ٣٠٠ — والإنتاج بقي على النشر السابق (تغييرك غير حيّ) |

## ٤. الإصلاح والتسليم

- أصلح **الجذر** لا العرض. إن كان العلاج يغيّر سلوكاً افتراضياً منتجياً، أو يمسّ قراراً محسوماً (دستور §٢)، أو يكلّف مالاً → اعرض خيارات (٢–٤، بتوصية) ولا تنفّذ.
- سلّم عبر `/ship`. رسالة الكومِت تقتبس سطر السجل الحاسم وتوثّق سلسلة السبب كاملة (دستور §٥-و).
- **إثبات الانحسار:** بعد بلوغ النشر READY، جرّب نفس المدخل إن أمكن من طرفك، وإلا اطلب من صاحب النشر تجربة محددة («ولّد بنفس الفكرة») ثم افحص السجلات بعدها — اختفاء التوقيع أو تبدّله إلى توقيع جديد كلاهما معلومة.
- في تقريرك افصل صراحة: ما أُصلح وثبت، وما يبقى مفتوحاً بانتظار قرار/تجربة.
